# 裁定台帳の作り方

「同じ判断を二度聞かない」ための仕組み。司令塔キットの中で、地味だが一番効く部品。

## やり方
1. 人間が判断を下したら、司令塔がルール案を1行で出す
   - 形：「ルール案：〇〇。範囲：〇〇。見直し：〇〇」
2. 承認されたものだけを台帳に入れる。承認されなかったものは、その日のメモに「保留」で残す
3. 台帳の各行には次を持たせる
   - ID（R-001 のような通し番号）
   - 本文（ルールそのもの）
   - 範囲（どの仕事・どの相手に効くか）
   - 条件・例外
   - 由来（いつ・誰の裁定か）
   - 見直し日
   - 状態（現行／置換済み）
4. 古いルールは消さない。「置換」にして経緯を残す。条件つきの判断（「この店だけ」「今月だけ」）を要約で落とすのが一番危ない

## 置き場所
- どのAIからも読める共有ドライブ等に「正本」を置くのがおすすめ（筆者運用では Google Drive の共有フォルダ）
- 司令塔のメモリには要約だけを持つ。正本と食い違ったら正本が勝つ
- 正本を書き換えるのは司令塔だけ（本人の承認後）。部下AIには、その仕事に必要なルールを指示書に添えて渡す。複数が同時に書くと現行ルールが競合するため
- 正本が読めないときは、古い要約で進めず止まる

## 注意
- 台帳は自動整理で書き換えない。要約や統合で条件が落ちる事故が起きる
- 台帳と矛盾する指示が来たら、司令塔は黙って従わず「例外か、ルール変更か」を確認する
