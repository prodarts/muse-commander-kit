# セッションルール：新規が基本、再開は条件付き

部下AI（Claude Code／Codex）に作業を投げるときの決めごと。実測をもとに決めた。

## 実測で分かったこと
（筆者環境での観測：2026年11月、Claude Code と Codex のセッション記録から。モデルや使い方で数字は変わるので、一般の目安ではなく「筆者はこう測れたのでこのルールにした」という根拠として読んでください）
- 新規セッションの読み直しは1回あたり約1万〜4万トークン
- 育ったセッションを再開すると、往復ごとの読み直しの合計が10万〜90万トークン規模になることがある
- つまり「会話の継続」に払っているコストは、引き継ぎそのものではなく**長生きしたセッションと往復の回数**
- 「前回の文脈の大きさ」は、各 CLI のセッション記録や使用量表示で測る。測れないときは安全側に倒して新規セッションにする

## ルール
- 基本は新規セッション（`claude -p` / `codex exec`）。状態は会話ではなくファイルで渡す
- 再開（resume）してよいのは、次の全部を満たすときだけ
  - 同じ成果物への追修正である
  - 前回から1時間以内
  - 前回の文脈がおおよそ8万トークン未満
  - 対象ファイルを他の誰も編集していない
  - 修正が3往復以内
- 再開は必ずセッションIDを明示する。「直前のセッションを再開」のような曖昧な指定は、並行作業の別セッションを拾う事故のもと
- 派遣ごとにセッションIDをプロジェクトフォルダに記録する

## なぜファイルで渡すのか
会話は消えるが、ファイルは残る。指示書（ブリーフ）と報告書がファイルに残れば、司令塔が交代しても、別のAIが続きを拾える。これが「AIに指揮系統を持たせる」ことの実体でもある。
